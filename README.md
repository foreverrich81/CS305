# CS305
Software Security


Artemis Financial is a financial services company that provides investment and financial planning solutions for its customers. The company wanted to improve the security of its software application because it handled sensitive financial data and needed to protect customer information from cyber threats. The primary issue was identifying and addressing vulnerabilities within the application. To solve this, a comprehensive security assessment was performed, including dependency checks and vulnerability analysis. The goal was to strengthen the application's security, ensure data integrity and confidentiality, and help Artemis Financial meet industry security standards and maintain customer trust.

When identifying Artemis Financial’s software security vulnerabilities, I used the dependency-check tools to analyze the application and identify known vulnerabilities in third-party libraries. I carefully reviewed the scan results, applied appropriate fixes, and suppressed false positives that were incorrectly flagged as vulnerabilities. This ensured the security report was accurate and focused only on legitimate risks, making remediation efforts more effective and reducing unnecessary work.

Coding securely is important because it protects sensitive data, prevents unauthorized access, and reduces the risk of cyberattacks. For a company like Artemis Financial, secure software helps maintain customer trust and supports compliance with industry security standards. Software security adds value by protecting company assets, reducing the likelihood of costly data breaches, improving system reliability, and preserving the organization's reputation. By accurately identifying real vulnerabilities and eliminating false positives, organizations can focus their resources on addressing genuine security threats and maintaining a stronger overall security posture.

One challenging but valuable part of the vulnerability assessment was determining which reported vulnerabilities were actual security risks and which were false positives. The dependency-check scan generated several findings, and I had to research them, review the affected libraries, and decide whether they genuinely impacted the application. Learning how to suppress false positives while documenting the reasoning behind those decisions helped improve the accuracy of the assessment and ensured that attention was focused on real security threats.

The most helpful aspect of the assessment was gaining hands-on experience with security analysis tools and the remediation process. It showed me how vulnerabilities are identified, prioritized, and addressed in a real-world software project. This experience strengthened my understanding of secure coding practices and demonstrated the importance of regularly assessing applications to maintain a strong security posture.

I increased layers of security by addressing identified vulnerabilities, updating insecure dependencies, implementing secure coding practices, and validating the results through additional vulnerability scans. I also reviewed and suppressed false positives when appropriate, ensuring that security efforts focused on legitimate risks. These actions helped create a defense-in-depth approach by reducing potential attack surfaces and strengthening the application's overall security.

In the future, I would use vulnerability assessment tools such as OWASP Dependency-Check, static code analysis tools, and vulnerability databases like the National Vulnerability Database (NVD) to identify and evaluate security risks. To decide which mitigation techniques to use, I would consider the severity of the vulnerability, its potential impact on the system, and industry best practices. This approach would help prioritize remediation efforts and ensure that the most critical security issues are addressed first.

I ensured the code and software application remained functional and secure by testing the application after making security-related changes and verifying that all features continued to operate correctly. After updating dependencies and refactoring the code, I rebuilt and ran the application to confirm that no functionality was broken. I also followed secure coding practices to reduce the risk of introducing security weaknesses during the refactoring process.

To verify that new vulnerabilities had not been introduced, I reran the OWASP Dependency-Check scan and reviewed the results. Comparing the new scan results with the previous assessment allowed me to confirm that identified vulnerabilities had been remediated and that no additional security issues had been created. I also reviewed any new findings to determine whether they were legitimate vulnerabilities or false positives, helping ensure the application's security posture improved without sacrificing functionality.

The resources and tools I found most valuable were OWASP Dependency-Check, the National Vulnerability Database (NVD), the Common Weakness Enumeration (CWE) database, Oracle's Java Security Standard Algorithm documentation, and the book Iron-Clad Java: Building Secure Web Applications by Jim Manico and August Detlefsen. These resources helped me identify known vulnerabilities, understand common software weaknesses, research secure cryptographic algorithms, and apply secure coding practices when remediating security issues. The OWASP Dependency-Check Maven plugin was especially useful for scanning project dependencies and identifying vulnerabilities that required further investigation.

In future projects, I will continue using vulnerability assessment tools, security databases, and secure coding references to evaluate and mitigate security risks. The vulnerability assessment process flow diagram reinforced the importance of architecture reviews, input validation, cryptography, secure API interactions, code reviews, and creating mitigation plans as part of a comprehensive security assessment. These resources and practices will help me build more secure applications, accurately evaluate vulnerabilities, and implement effective remediation strategies.

For future employers, I could showcase the vulnerability assessment report, the remediation process, and the refactored application code from the Artemis Financial project. This work demonstrates my ability to use security tools such as OWASP Dependency-Check, analyze vulnerability reports, research security risks using resources like the NVD and CWE databases, and implement appropriate fixes. It also shows that I can distinguish between legitimate vulnerabilities and false positives, which is an important skill in cybersecurity and software development.
